# `self.arm` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every kitchen capability `self.arm`: the students' `SheppyArm` API reproduced exactly, every arm driver interface beside it, driver-state tracking, and one mount-aware PyBullet sim per engine.

**Architecture:** Three pure-Python modules (`sim`, `sheppy_arm`, `driver_state`) hold everything that does not need ROS and are tested against golden outputs recorded from the students' code. One rclpy module (`arm.py`, `ArmInterface`) talks to the driver and is tested against a fake driver node. `CapabilityEngine` owns one `ArmInterface` as `self.arm`, opens its ROS resources on first use inside `execute()` and destroys them when `execute()` ends.

**Tech Stack:** ROS 2 Humble, rclpy, Python 3.10, numpy, scipy, PyBullet, pytest, Docker.

**Spec:** `docs/superpowers/specs/2026-10-27-shared-arm-design.md`

## Global Constraints

- Reference student code: `https://github.com/dhyi-svg/feeding-deployment` at `microwave-wip@7bc328ae` (`microwave/sheppy_arm.py`, `microwave/microwave_common.py`). Ported code is copied, not rewritten, except where a task names a change.
- Golden tolerance: joints and trajectory samples reproduce to `1e-6` rad (`1e-6` s for times).
- Driver contract: joint names `arm_joint_1`..`arm_joint_7`; every Cartesian pose in `arm_mount`; `/ee_state` is the flange, tool frame = flange + `0.120` m along flange z.
- The engine and `self.arm` never call `/acquire_control` or `/release_control`. A token is sent when the engine has one; otherwise commands carry none.
- Arm ROS resources exist only between the first arm call in an `execute()` and the end of that `execute()`.
- No `print()` in `capability_engine` (Ruff); log through the node's logger with the students' message text.
- Every tunable is a named constant with a one-line meaning, exposed as a ROS parameter `arm.<name>` with today's value as default (Task 11). No unexplained literals in new code.
- Production images stay `FROM ghcr.io/rammp-org/rammp-base:1.1.0-jp6` (arm64); the base tag is the arm/common interface pin.
- One `make_sim()` copy per process; `self.arm` uses the same copy.

## Review Focus

1. **Joint indexing on the driver's URDF.** The driver model is rooted at `arm_mount` with a fixed mount joint, and has gripper joints; `solve_ik` must still return `arm_joint_1..7` in order. Expect FK of the solution to land on the target on the flatbot URDF. Test: Task 4 `test_solve_ik_flatbot_fk_round_trip`.
2. **State from a previous action.** The first `get_state()` in a new `execute()` must wait for fresh `/joint_states`, never return values cached in the last action. Test: Task 7 `test_state_cleared_between_actions`.
3. **Cancel while blocked in a motion.** A cancel during `move_joints` or `go_to_*` must cancel the driver goal and raise `Cancelled` within 0.5 s, not after the trajectory. Tests: Task 8 `test_cancel_during_move_joints`, Task 9 `test_cancel_during_go_to`.
4. **An exception inside `with self.arm.stream(...)`.** The session must be zeroed and closed before the exception propagates. Test: Task 10 `test_stream_closes_on_exception`.
5. **A goal the driver rejects outright** (not accepted, e.g. `NOT_AUTHORIZED` under enforced arbitration with no token) must return `False` / raise with the "no control token" message promptly, never hang. Test: Task 8 `test_goal_rejected_without_token`.
